# Debian-family package profile notes

Installer package setup is gated by exact distro IDs and supported versions; `ID_LIKE` alone is never accepted. When the package step is approved, package candidates are checked with `apt-cache policy` before `apt-get update`, installation, or file placement. The core rice requires i3 >= 4.22 (including its `gaps` and `tiling_drag` directives). If the Ubuntu native candidate is older, package setup offers the sur5r repository recommended by i3, with a separate default-no approval before any system changes. After package setup, the installed i3 version and planned configuration are checked using `i3 --version` and `i3 -C` before managed files are placed. Parser checks do not start a session or execute configuration startup commands. `--files-only` remains an explicit bypass for users who manage dependencies themselves; they must ensure i3 >= 4.22 before starting the session. `--yes` does not bypass the parser check. Missing candidates other than Fastfetch stop that operation and identify the missing packages; no repository is added to repair unrelated missing packages. `--dry-run` does not check candidates or install anything.

## Ubuntu evidence and limitation

Ubuntu 26.04 package setup is enabled provisionally with native packages, mandatory candidate checks and the existing i3 >=4.22 check. The sur5r fallback remains restricted to 22.04/24.04; no older suite is substituted on 26.04. Full VM validation is pending.

The official Ubuntu package archives show `i3-wm` for Jammy, Noble, and Resolute. Ubuntu 22.04's native i3 is below the rice's 4.22 minimum. For Ubuntu 22.04/24.04 only, the installer can offer i3's recommended sur5r repository after separate explicit approval. It verifies the pinned sur5r-keyring 2025.12.14 package by SHA256 and package metadata, installs the local package, and writes `/etc/apt/sources.list.d/sur5r-i3.list` with HTTPS and `signed-by=/usr/share/keyrings/sur5r-keyring.gpg`. `/etc/apt/preferences.d/sur5r-i3` allows only i3, i3-wm, i3status, i3lock and sur5r-keyring from this origin; other packages have priority -1. A refreshed candidate must meet the minimum. Existing mismatched files or symlinks are refused. These system files and keyring remain after restore or a later apt failure; restore only manages user dotfiles. No session is restarted. No repository changes or downloads occur with `--yes`, `--files-only` or `--dry-run`. The compatibility/version and parser guards prevent placing an unusable config rather than deleting features as a workaround. Fastfetch is absent from the Jammy and Noble archive indexes, while the official Launchpad source index lists Fastfetch for Resolute 26.04 in Universe. The default selection keeps Fastfetch included. If its native candidate is absent, the approved package step downloads the official fastfetch-cli/fastfetch 2.70.0 release `.deb` for amd64/arm64 and verifies its pinned SHA256, package name, architecture and version before any apt changes. The Fastfetch fallback adds no PPA or repository. Unsupported fallback architectures or verification/download failures stop before configuration placement. Private temporary staging is removed afterward; apt may print its standard unsandboxed-local-file warning because `_apt` cannot traverse that staging directory. Sandbox settings are not changed. Restore does not uninstall packages. Ubuntu 26.04 package setup is provisional and retains all package and i3 compatibility checks. New Ubuntu support still needs clean-VM installation and desktop-session testing.

Debian 13 remains the previously supported target. Kali and Parrot are exact-ID candidates only; their package candidates and desktop compatibility have not been independently established in this work, so treat them as provisional pending candidate preflight and clean-VM testing. No repository is added automatically.
